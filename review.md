## Daily Review Rules

- A **new review entry must be created for each day**
- Each entry must be timestamped (ISO format preferred: `YYYY-MM-DD HH:mm`)
- All findings must be appended to this file chronologically
- Previous reviews must never be overwritten

---

## Update Behaviour

If a review for the same day already exists:

- Do not duplicate it
- Instead, append an **Update Notes** section under that day's entry
- Clearly describe what changed since the last update

---

## Required Structure Per Entry

Each daily entry must follow this format:

```markdown
## Review - YYYY-MM-DD HH:mm

### Project Review Summary

### Completed Work Verified

### Tickets Closed

### Tickets Requiring Follow-Up

### Roadmap Updates

### Risks and Blockers

### Recommended Tickets for Today

### Suggested Development Order

---

### Update Notes (if applicable)

- Any corrections, changes, or newly discovered information since initial review
